     GET /api/v1/accounts with transfer history (naive N+1 on purpose)

     Context

     The user wants an endpoint that lists every account with its transfers, and
     wants to watch in the SQL log how many queries a naive lazy-loading
     approach runs (1 query for accounts + 1 per account for its transfers). No
     JOIN FETCH / @EntityGraph. TransferHistory also gets a direction enum, and
     each transfer now writes two rows: OUTGOING on the source, INCOMING on the
     target. The history table stays empty in data.sql.

     Path: the controller is mapped to api/v1/accounts, so the endpoint is GET 
     /api/v1/accounts. Enum values are spelled INCOMING / OUTGOING (fixing the
     typos in the request).

     Changes

     1. model/TransferDirection.java (new): enum TransferDirection { INCOMING, 
        OUTGOING }.
     2. schema.sql: add to transfer_history
        direction VARCHAR(8) NOT NULL + CONSTRAINT ck_direction CHECK (direction
        IN ('INCOMING','OUTGOING')).
     3. model/TransferHistory.java: add
        @Enumerated(EnumType.STRING) @Column(nullable = false, length = 8) 
        private TransferDirection direction;
        and a direction param in the constructor. Risk: Hibernate 7 on H2 may
        expect a native enum column type and fail ddl-auto=validate against
        VARCHAR; if so, add @JdbcTypeCode(SqlTypes.VARCHAR) on the field.
     4. model/Account.java: add the inverse side, lazy by default:
        @OneToMany(mappedBy = "account") private List<TransferHistory> transfers
        = new ArrayList<>();
        Doesn't change the schema (FK stays on transfer_history.account_id).
     5. service/TransferService.java: save two records — (source, 
        target.accountNumber, amount, now, OUTGOING) and (target, 
        source.accountNumber, amount, now, INCOMING) (saveAll(List.of(...))).
     6. DTOs (records in dto/, same style as LimitsResponse.from):
        - TransferHistoryResponse(Long id, TransferDirection direction, String 
          counterpartyAccountNumber, BigDecimal amount, Instant timestamp) +
          from(TransferHistory)
        - AccountResponse(Long id, String accountNumber, BigDecimal balance, 
          List<TransferHistoryResponse> transfers) + from(Account)
     7. service/AccountService.java: @Transactional(readOnly = true) 
        List<AccountResponse> getAllAccounts() = accountRepository.findAll()
        then map each account (touching getTransfers() triggers one lazy SELECT
        per account). Mapping must happen inside the transaction because
        spring.jpa.open-in-view=false — mapping in the controller would throw
        LazyInitializationException.
        → Learn by Doing: the user writes this mapping body (TODO(human)).
     8. controller/AccountController.java: @GetMapping public 
        List<AccountResponse> getAllAccounts().
     9. Optional, for the user's goal:
        spring.jpa.properties.hibernate.generate_statistics=true in
        application.properties logs the JDBC statement count per session.

     Tests

     - TransferServiceTest: capture saveAll list → 2 records, check
       directions/counterparties.
     - TransferIntegrationTest: expect 2 history rows (OUTGOING on source,
       INCOMING on target).
     - PersistenceTest: pass direction in the existing history test; assert it
       round-trips.
     - AccountServiceTest (mock findAll):
       - maps accounts + transfers (directions, counterparties, amounts)
       - no accounts in DB → findAll returns empty list → result is an empty
         list (no exception)
       - account without history → its transfers is an empty list, not null
     - AccountControllerTest (mock service):
       - GET /api/v1/accounts returns the JSON list with nested transfers
       - no accounts → 200 with []
       - account without history → 200, $[0].transfers is []
       - missing headers → 401/400 ErrorResponse (same interceptor, sanity check
         on the new route)
     - TransferIntegrationTest (or new test): make a transfer, then GET 
       /api/v1/accounts shows 1 transfer on each account with correct
       directions.

     Verification

     - ./mvnw test
     - ./mvnw spring-boot:run, then POST a transfer and GET /api/v1/accounts
       with Authorization: Bearer token-123 and X-Correlation-Id; the log should
       show 1 select ... from account + 2 select ... from transfer_history 
       where account_id=? (N+1 with N=2).
