     Fix N+1 in GET /api/v1/accounts with @EntityGraph

     Context

     AccountService.getAllAccounts() was naive on purpose:
     accountRepository.findAll() (1 SELECT) and then one lazy
     SELECT ... from transfer_history where account_id=? per account when
     toResponse reads getTransfers().
     Now that the N+1 has shown up in the SQL log, the goal is to load accounts
     and their transfers in one query
     with @EntityGraph.

     Approach

     Add a dedicated repository method instead of overriding findAll():

     // AccountRepository
     @EntityGraph(attributePaths = "transfers")
     @Query("select a from Account a")
     List<Account> findAllWithTransfers();

     Why not override findAll(): the override would make every findAll() caller
     (e.g. PersistenceTest, future
     batch code) join the whole history table. A named method makes the eager
     fetch visible at the call site and keeps
     findAll() cheap. The @Query is needed because findAllWithTransfers isn't a
     valid derived-query name.

     Notes to keep in mind (no code needed):
     - Hibernate 6+/7 deduplicates root entities of a collection fetch join, so
       no DISTINCT is required.
     - transfers is a List (a bag). One bag per query is fine; fetching a second
       bag collection in the same graph
       would throw MultipleBagFetchException.
     - It's a LEFT JOIN, so accounts without history still come back, with an
       empty list.

     Changes

     1. src/main/java/com/example/banking/repository/AccountRepository.java —
        add findAllWithTransfers() as above.
        → Learn by Doing: the user writes this method (TODO(human)); it's the

     2. src/main/java/com/example/banking/service/AccountService.java
        - getAllAccounts() calls findAllWithTransfers().

          (open-in-view off).
        - toResponse Javadoc: drop "(1 select)"; it no longer triggers a query.
     3. src/test/java/com/example/banking/service/AccountServiceTest.java — stub

        findAll() in the three getAllAccounts* tests.

        test proving the fetch:

        Hibernate.isInitialized(account.getTransfers()) would be wrong here: the

        returns an unmodifiableList wrapper, not the Hibernate collection.
