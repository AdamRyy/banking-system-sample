## Final plan

### Context
`GET /api/v1/accounts` lists every account with its whole transfer history. It is the only reason
`Account` has the inverse `@OneToMany transfers` list and `AccountRepository.findAllWithTransfers()` (entity graph
added to fix the N+1). We're removing the endpoint and the inverse side. `TransferHistory.account` stays as the owning
`@ManyToOne`. The DB schema doesn't change: the FK `transfer_history.account_id` belongs to the owning side.

### Production changes

1. **`model/Account.java`**
   - Remove the `transfers` field (`@OneToMany` + `@OrderBy`) and `getTransfers()`.
   - Keep `recordTransfer(...)` as a factory: it only builds `new TransferHistory(this, ...)` and returns it (no `transfers.add`).
     So the `TransferHistory` constructor stays package-private and `TransferService` and the tests stay as they are.
     Javadoc: "The only way to create a TransferHistory for this account."
   - Remove the unused imports: `OneToMany`, `OrderBy`, `ArrayList`, `Collections`, `List`.
2. **`model/TransferHistory.java`**: keep the `@ManyToOne` unchanged. Change the constructor Javadoc (line 66) to
   `Use {@link Account#recordTransfer}.` (it no longer adds the row to a list).
3. **`repository/AccountRepository.java`**: remove `findAllWithTransfers()` and the `EntityGraph`, `Query`, `List` imports.
4. **`service/AccountService.java`**: remove `getAllAccounts()` and `toResponse()`, plus the `AccountResponse`,
   `TransferHistoryResponse`, `List` imports.
5. **`controller/AccountController.java`**: remove the `@GetMapping` `getAllAccounts()` and the `AccountResponse`, `List` imports.
6. **Delete `dto/AccountResponse.java` and `dto/TransferHistoryResponse.java`.** Nothing else uses them.

`TransferService` needs no change: it already gets the rows from `recordTransfer` and saves them with `saveAll`.

### Test changes

- **`AccountControllerTest`**: remove the 5 tests for `GET /api/v1/accounts` (lines 110–172:
  `returnsAllAccountsWithTheirTransfers`, `returnsEmptyArrayWhenThereAreNoAccounts`,
  `returnsEmptyTransfersForAccountWithoutHistory`, `allAccountsRequiresAuthorization`,
  `allAccountsRequiresCorrelationId`) and the imports only they use (`AccountResponse`, `TransferHistoryResponse`,
  `TransferDirection`, `BigDecimal`, `Instant`, `List`, `HttpHeaders`, `CORRELATION_ID_HEADER`, `VALID_AUTHORIZATION`).
- **`AccountServiceTest`**: remove the 3 `getAllAccounts*` tests and the imports they leave unused (`AccountResponse`,
  `TransferHistoryResponse`, `TransferDirection`, `Instant`, `List`, `assertTrue`).
- **`TransferServiceTest`**: remove lines 138–140 (the inverse-side `getTransfers()` asserts and their comment).
- **`AccountRepositoryIntegrationTest`**: remove `accountTransfersAreLoadedLazilyFromHistory` and
  `findAllWithTransfersFetchesTransfersInTheSameQuery`, then the imports they leave unused (`TransferDirection`,
  `TransferHistory`, `SessionFactory`, `Statistics`, `assertTrue`, and `historyRepository` if nothing else uses it).
- **`TransferIntegrationTest`**: remove `allAccountsListShowsEachSideOfTheTransfer` and
  `allAccountsListShowsEmptyTransfersBeforeAnyTransfer`. `get` stays imported because the limits check uses it.
  The history rows are still checked through `TransferHistoryRepository.findAll()` in `transferMovesMoneyBetweenSeedAccounts`.

### Not changed
- `schema.sql` / `data.sql`: the FK lives on `transfer_history`.
- ADRs / CLAUDE.md: neither mentions the collection or the endpoint. `docs/specs/*` are historical logs and stay as they are.

### Verification

2. Grep `src/` for `getTransfers|findAllWithTransfers|AccountResponse|TransferHistoryResponse|OneToMany`. It should find nothing.
3. Optional manual check after `./mvnw spring-boot:run`: `GET /api/v1/accounts` with valid headers returns the
   uniform 404 `ErrorResponse` (`NOT_FOUND`). `POST /api/v1/transfers` still returns 201.
